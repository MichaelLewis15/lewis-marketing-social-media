# daily-social (Lewis Marketing only)

Two posts every day for **Lewis Marketing only** (never a client account): a **morning** post and an **afternoon** post, always covering the next 7 days. Fill whichever slot is empty with an educational or engagement post. Slot times are per platform (America/Chicago), from `settings.postingTimes`:
- Morning: Google Business 8:00, Facebook 8:30, Bluesky 8:30, Instagram 9:00, Threads 9:00, LinkedIn 11:00 (weekdays only).
- Afternoon: Facebook 1:00 PM, Threads 1:00, Bluesky 1:00, Instagram 1:30, LinkedIn 3:30 (weekdays only, and only if it is 4+ hours after that day's LinkedIn post), Google Business 1:00 (only if the day has no other GBP post).
- Keep 3+ hours between a day's morning and afternoon post on the same channel (shift the afternoon later if the morning post is late). Evening extras (7 PM) don't count as a slot.
- Basis: Sprout Social 2026 and Buffer 2026 best-time studies (links in settings.postingTimes). Revisit with our own analytics monthly.

## Each run
1. **Settings.** Read `dsconfig/settings` (ArtifactData get). Confirm the location (above).
2. **Window.** Tomorrow through today + 7 days, Chicago time.
3. **Busy slots.** A slot (morning = before noon, afternoon = noon to 5 PM, Chicago time) is taken if any of these has a post in it:
   - HighLevel `get-posts` (POST body `{type:"all", skip:"0", limit:"100", fromDate, toDate}`; page with skip; the response is large, so save it and parse with code).
   - `settings.calendarDates`, the hub collections `daily`, `posts` (LEWIS-OS) and `edits` (an edit's `date` moves a post).
   Also skip `settings.quietDates` and LEWIS-OS closures (artifact https://claude.ai/artifact/E3pGawMbWLNG42qs1PqNfY, `settings/main.closures`). Never put two posts in the same slot. If a daily doc already exists for a date and slot, leave it alone. Daily doc ids: `ds-<date>-am` / `ds-<date>-pm`.
4. **Topic per empty slot.** Morning slots lean Teach (how-to, myth, checklist); afternoon slots mix Teach with Engage (poll, question, local shout-out) so the day doesn't feel repetitive. Never the same service area twice in one day. First check `settings.platformPlaybook` (weekly trend radar: current best practice per platform; write each platform's version to it), `settings.whatWorks` (weekly social-sync notes: favor winning formats/topics) and `settings.ideaQueue` (weekly influencer-watch ideas: use one if it fits, keep any credit line, then remove it from the queue). Educational ("Teach"). One specific problem a small-business owner in the ICP has. Never repeat a topic in `recentTopics` from the last 60 days, or one already on the calendar in the window. Sources, in order: the dossier and ICP in settings, the Drive sheet "October Content Ideas" (and newer content-ideas sheets), the latest Lewis Marketing blog posts (lewismarketingoc.com is not reachable from the cloud sandbox; try WebSearch, and if it fails, flag it), the links directory, and what is already in the Social Planner. Vary the service area (websites, SEO, Google Ads, Meta Ads, CRM/automation, email, content, analytics, reviews/local).
5. **Copy** (brand voice in settings; no emojis anywhere in captions, first comments or alt text; no invented stats; any statistic needs a credible source link; never shorten "Piper Financial Group"):
   - Hooks (Michael's rule): every post opens with a hook (first line of the caption, first 2 seconds of a video). Use a double hook when it fits: a second line or beat (caption line 2, or about 3-5 seconds into a video) that raises the stakes or opens a loop the post pays off, e.g. "Your Google profile is losing you calls." then "And the fix takes 10 minutes." Do not overuse it: a double hook on roughly 1 in 3 posts at most, mainly reels and the strongest posts, and never two days in a row on the same account. Every hook must be true and paid off in the post; no clickbait.
   - Hook line on the problem (under 12 words; a question or number), a simple numbered how-to (3-5 steps), one short paragraph on how Lewis Marketing helps, then hashtags per channel.
   - Hashtags and search keywords (Michael's rule: every post, every channel, built for maximum organic reach). Follow `settings.seoRules` exactly. Put the keyword phrase a small-business owner would search in the first line and in the alt text; add a local keyword (Northwest Iowa, Sioux Center, Orange City, Siouxland) where natural. Hashtag counts: Instagram max 5 (hard limit: 2 topic + 1 audience + 1 local + #LewisMarketing), Facebook 2-3 (incl. 1 local), LinkedIn 3, Threads exactly 1 topic tag, Bluesky 1-2, TikTok 3-5 (search phrase first), YouTube Shorts keyword-first title under 70 chars + 3 hashtags in the description, Google Business none (service + town keywords instead). Never generic tags (#reels, #fyp, #viral, #explore). Before scheduling, count each caption's hashtags against these limits.
   - The CTA link is copied exactly from `settings.links`. Never invent or edit a URL. If no saved link fits, use `website` and flag it.
   - Platform versions (hashtag counts per `settings.seoRules`): facebook (link only in the first comment), instagram (says the link is in the first comment), threads (max 500 chars), linkedin (longer, professional), bluesky (max 300 chars), gbp (first line `UPDATE POST · Button: Book → <link>` or `Learn more → <link>`, blank line, then text with no links, phone numbers or emails; max 1500).
   - `firstComment`: one sentence plus the exact saved link. Also write `alt` (describe the graphic, mention Howie if he is in it) and a short `storyTip`.
6. **Image.** First search the HighLevel media library (`fetch-media-content`, query `{altType:"location", altId:<loc>, type:"file", limit:"50", query:"<keyword>"}`) for a branded Lewis Marketing graphic that clearly fits the topic; use its CDN URL if one does (GBP still needs a 4:3 version, so render one if the library image is not 4:3). Otherwise render one with the engine: write a spec JSON, run `python3 daily-social/engine/render_daily.py spec.json .` inside the repo clone (needs Pillow + numpy), look at the PNG, fix any overlap, commit `daily/<date>.png` and `daily/gbp/<date>.png`, push. **Vary the design (Michael's rule: graphics must not all look the same).** Set `"layout"` in the spec and never use the same layout twice in a row across both daily slots (check the previous slot's daily doc `asset.layout`); rotate through all 17 before reusing one when content allows (Myth Monday may keep `myth`). Put **Howie** (poses idle, pointL, pointR, wave, cheer; default `{"pose":"pointL","x":985,"feet":1112,"h":215}`) in every graphic, never covering text. To add him to an existing image or reel, use `daily-social/howie-tools/place_howie.py` and `howie_reel.py`. Any video made must follow the lewis-marketing-video skill (Howie always in videos).
7. **Save** `daily/ds-<date>` with: id, date, day ("Sat, Oct 31"), time "7:30 AM", pillar "Daily Social · Teach", series "Daily Social", topic (slug), title, goal, linkKey, ctaLink, hashtags, asset `{type:"graphic", file:<full image URL>, gbp:<full 4:3 URL>, note}`, alt, firstComment, storyTip, copy{facebook, instagram, threads, linkedin, bluesky, gbp}, status, createdBy "daily-social", createdAt.

## TikTok needs HighLevel-hosted video

Automatic fix (Nov 8, 2026): the GitHub Action `.github/workflows/tiktok-sync.yml` (tools/tiktok_sync.py, secret HL_TOKEN) runs every 30 minutes and on every push of an .mp4. It uploads the video of every scheduled TikTok post that is not yet on assets.cdn.filesafe.space into the "TikTok videos" folder and repoints the post. So: commit the .mp4 to the repo BEFORE creating the TikTok post, and the post is fixed within 30 minutes. The hub queue below is the backup.

TikTok rejects every video whose URL isn't on a domain HighLevel verified with TikTok ("The media URL isn't from a verified domain"). raw.githubusercontent.com is NOT verified; assets.cdn.filesafe.space (HighLevel Media Storage) is. Every other channel accepts the GitHub URL. The connector can't copy a video into Media Storage from a URL (hosted:true only links it), so:

1. Create the TikTok post (both TikTok accounts) with the GitHub video URL as usual. Keep TikTok in its OWN post, not combined with other channels.
2. Publish the video into the content hub artifact at its repo-relative path (files publish, keep each file under 15 MB; re-encode with ffmpeg -crf 25 -maxrate 1.4M if larger).
3. Write a doc to the hub db collection `ttq` with id `tt-<video basename>`: {file: "<repo-relative path>", name: "<basename>.mp4", label, first: <scheduleDate>, when: "<Day Mon D, H PM>", posts:[{id: <postId>, label, at: <scheduleDate>, body: <full edit-post body with the GitHub URL>}]}.
4. Michael's rule (Nov 8, 2026): every TikTok video is stored in HighLevel Media Storage in the folder "TikTok videos" (folder id 6af11ffa1ac4234dcd04e3de; also in hub dsconfig/tiktok). Before queuing, check fetch-media-content in that folder for a file with the same name and, if it exists, edit the TikTok post to that URL directly instead of queuing.
5. The hub uploads queued videos into that folder and edits the posts automatically whenever Michael opens it. If a queued TikTok post is less than 24 hours away and its doc has no hlUrl, say so in the run log so Michael opens the hub.

## Carousels (known HighLevel limit)
HighLevel's API keeps only the FIRST image on scheduled multi-image posts (tested Nov 7, 2026; drafts keep all images, scheduled/edited posts are trimmed to one, on every platform and with HighLevel-hosted images too). So never schedule a carousel as a multi-image post through the connector. Instead render it as a swipe-style reel with `python3 daily-social/howie-tools/swipe.py out.mp4 <music 0-3> slide1.png ... slideN.png` (9:16, music, animated Howie), post that video to Facebook/Instagram as a reel and to Threads, Bluesky and both TikTok accounts, and for LinkedIn build a PDF of the slides and flag Michael to attach it to the LinkedIn post in the Social Planner (document posts can't be attached by the API either).
